# Costs v2.2 — schema extensions

Status: approved 2026-05-26
Owner: @r13i
Depends on: v2.1 schema (already shipped)

## Goal

Close the four highest-impact schema gaps surfaced during Phase 1 data work, without overcomplicating the common-case (per-token text-only chat) shape. **Non-breaking, additive only.** `version: const 2` stays. All 84 existing rows validate unchanged. No data migration required.

## Non-goals

- No `version` bump. The const stays at `2` for the data envelope.
- No structured-pricing rewrite (Approach B in brainstorming). The common path stays flat.
- No subscription/overage modeling. Vendors who only sell plans get `confidence: medium` + notes — the current pattern works and has clear cost limits.
- No per-request inference modeling (Replicate, Fal.ai). Per-run-that-varies-by-length is per-second by another name; convert at ingest if a vendor publishes a stable rate, otherwise defer.
- No `image_input_per_mtok_usd` or `video_input_per_mtok_usd`. Defer until a second non-Gemini case appears (YAGNI per the project's own tenet).
- No data backfill in this PR. Existing rows continue to model audio rates / per-second pricing in `notes`; subsequent data-update PRs promote where applicable.

## Architecture

Edit five files:

```
costs/schema/llm.schema.json     ← add audio_input_per_mtok_usd + aggregators[]
costs/schema/stt.schema.json     ← add price_per_second_usd + aggregators[]
costs/schema/tts.schema.json     ← add price_per_second_usd + aggregators[]
web/lib/types.ts                  ← add matching TS types
docs/superpowers/specs/2026-05-26-costs-v2.2-design.md   ← this file
```

No new scripts, no new CI workflows, no data file changes.

## Schema deltas

### 1. `LLM.audio_input_per_mtok_usd`

```json
"audio_input_per_mtok_usd": { "$ref": "#/$defs/decimal" }
```

Optional row-level field. Concrete use case: Gemini bills audio input distinctly from text input. Today's structured `input_per_mtok_usd` captures the text rate; future Gemini rows can set `audio_input_per_mtok_usd` to the audio rate.

Semantics: when a model accepts audio input AND prices it differently from text/image/video input, this field carries the audio-specific rate. `input_per_mtok_usd` remains the canonical "text-default" rate.

If a row's modalities exclude `audio`, the validator does not enforce this — it's purely additive. Modalities array continues to be the source of truth for "what does this model accept."

Place in field-order after `input_per_mtok_usd` / `output_per_mtok_usd`, before the cache fields. The cluster of input-modality variants stays together if image/video rates land later.

### 2. `STT.price_per_second_usd`

```json
"price_per_second_usd": { "$ref": "#/$defs/decimal" }
```

Optional row-level field. **Either** `price_per_minute_usd` **or** `price_per_second_usd` must be present (the existing `price_per_minute_usd` required constraint is loosened to "one of"). Schema enforces this via a `oneOf` / `anyOf` constraint.

Concrete use case: Resemble AI publishes $0.0005/sec. Forcing it into per-minute as $0.03/min loses fidelity for sub-second-precision pricing.

When both are present, per-second is canonical and per-minute is derived (`price_per_minute_usd = price_per_second_usd × 60`). Validator does not enforce the relationship — it's a consistency check for the cost estimator.

Migration: existing 19 STT rows continue to validate unchanged (all currently use `price_per_minute_usd`).

### 3. `TTS.price_per_second_usd`

```json
"price_per_second_usd": { "$ref": "#/$defs/decimal" }
```

Same shape as STT. `price_per_1m_chars_usd` remains required for vendors that bill by character; `price_per_second_usd` is an alternative for vendors that bill by output-audio duration. Schema enforces "one of" via `anyOf`.

Concrete use case: not yet a Phase 1 row but anticipated for providers that bill output-audio-seconds (some current Hume / Resemble TTS variants).

### 4. Row-level `aggregators[]` (all three schemas)

```json
"aggregators": {
  "type": "array",
  "uniqueItems": true,
  "items": {
    "enum": ["openrouter"]
  }
}
```

Optional field. Semantically distinct from `deployment_options[]`:

- `deployment_options[]` — direct hosts (vendor's own API + Bedrock/Vertex/Azure/Together/Fireworks/Groq/Replicate/Dashscope)
- `aggregators[]` — routers that proxy to multiple direct hosts (OpenRouter today; others later)

When `aggregators[]` is set, the row's structured price may reflect the aggregator-routed rate, with at least one direct host also listed in `deployment_options[]` for transparency.

**Back-compat for `openrouter` in `deployment_options[]`:** the value stays in the enum (so v2.1 data still validates). Schema descriptions get a `deprecated: true` annotation on the `openrouter` enum value (informational only; JSON Schema doesn't reject deprecated values). Convention going forward: new rows use `aggregators[]`, existing rows can be migrated in subsequent PRs.

### Other

- Required-field changes: STT and TTS go from "`price_per_minute_usd` / `price_per_1m_chars_usd` required" to "at least one of (per-minute, per-second) / (per-1m-chars, per-second) required" via `anyOf`. Existing data still validates.
- `additionalProperties: false` stays on root, model, $defs.\* — new fields are explicitly declared.
- `version: const 2` stays.

## TypeScript deltas (web/lib/types.ts)

```typescript
export type LLMRow = CommonFields & {
  // ... existing fields
  audio_input_per_mtok_usd?: string;
  aggregators?: Aggregator[];
};

export type STTRow = CommonFields & {
  // ... existing fields
  price_per_minute_usd?: string; // changed: now optional
  price_per_second_usd?: string; // new
  aggregators?: Aggregator[];
};

export type TTSRow = CommonFields & {
  // ... existing fields
  price_per_1m_chars_usd?: string; // changed: now optional
  price_per_second_usd?: string; // new
  aggregators?: Aggregator[];
};

export type Aggregator = "openrouter";
```

Note the STT and TTS required-field relaxation requires changing `price_per_minute_usd?` (was required) and `price_per_1m_chars_usd?` (was required) from `string` to `string?`. TS doesn't enforce the `oneOf` constraint — that lives in the JSON Schema only.

## Validation

- `pnpm costs:validate` continues to pass against current data (19 STT + 23 TTS rows all use `price_per_minute_usd` / `price_per_1m_chars_usd`).
- `pnpm site:build` continues to pass (TS optional-field changes are additive).
- jq referential checks continue to pass.

## Risks

- **`anyOf` constraint complexity.** JSON Schema's `anyOf: [{required: [A]}, {required: [B]}]` works but error messages get confusing when neither is present. Mitigation: document in `costs/README.md` that one of the per-unit fields must be present per category.
- **Aggregator-vs-host semantic split is judgment-heavy.** OpenRouter is unambiguously an aggregator. Together AI sells access to many models but operates its own GPUs — direct host. Replicate is borderline (hosts community models but also routes). Mitigation: document the distinction in the schema description and the README. As more routers emerge (e.g. Lepton, Anyscale), add to the enum or split further.
- **Per-second STT/TTS pricing migration ambiguity.** A few existing rows could be more naturally expressed in per-second. We do NOT migrate them in this PR. Future data PRs can switch per-row.

## Migration

No data changes. All existing rows validate without modification.

Subsequent data PRs (post-v2.2) can opportunistically:

- Populate `audio_input_per_mtok_usd` on Gemini rows (values are already in notes)
- Migrate `openrouter` references from `deployment_options[]` to `aggregators[]` on the Meta Llama rows
- Switch Resemble AI (if added in a future TTS PR) to `price_per_second_usd`

## Compatibility

Strictly non-breaking. v2 consumers continue to validate. New optional fields are declared so producers can add them and validation accepts. Schema files served at canonical `$id` URLs update in place.

## Out of scope

- Per-modality input pricing beyond audio (image, video) — defer until second concrete case
- Subscription / overage modeling — defer (current `confidence: medium` + notes works)
- Per-request inference (Replicate, Fal.ai) — defer (per-second covers most needs)
- Cache_read_ratio for Qwen-style percentage caching — defer (current Qwen rows have it in notes)
- Validator extensions beyond JSON Schema
- Renderer / UI surfacing the new fields
