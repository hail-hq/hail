# Costs v0.2.1 — schema extensions

Status: drafted 2026-05-19
Owner: @r13i
Depends on: v0.2 schema (in `costs/schema/llm.schema.json`, already shipped)

## Goal

Address five recurring schema gaps surfaced during Phase 1 data work (PR3 Gemini, PR5 Mistral, PR6 DeepSeek, PR8 xAI, PR9 Alibaba+Perplexity) by adding four optional fields and one enum value. **Non-breaking, additive only.** `version: const 2` stays. Existing v2 rows validate unchanged.

## Non-goals

- No `version` bump. The const stays at `2`.
- No data backfill in this PR. Existing rows (Gemini Pro's per-tier cache rate, Perplexity per-search fees, Llama Maverick OpenRouter routing) keep their current shape until a separate data-update PR.
- No per-modality input pricing (Gemini audio rates differ from text). That's the biggest design question and the current workaround (document in notes) has worked. Defer to v3.
- No `cache_read_ratio` for Qwen-style percentage-of-tier caching. Wait until a second case lands.
- No web-renderer changes beyond the TypeScript types. UI doesn't need to surface these fields yet.

## Architecture

Edit four files:

```
costs/schema/llm.schema.json     ← extend $defs.model with 3 new optional props + extend pricing_tiers items + extend deployment_options enum
web/lib/types.ts                  ← add 3 optional fields to LLMRow + 1 optional field to pricing_tiers items + extend DeploymentOption type
docs/superpowers/specs/2026-05-19-costs-v0.2.1-schema-design.md   ← this file (already exists)
costs/README.md                   ← optional one-line bump if the new fields warrant contributor mention
```

No data file changes. No new CI workflows. No new scripts.

## Schema deltas

### 1. `pricing_tiers[]` items gain optional `cache_read_per_mtok_usd`

Current shape (per v2):

```json
"pricing_tiers": {
  "type": "array",
  "minItems": 1,
  "items": {
    "type": "object",
    "additionalProperties": false,
    "required": ["threshold_tokens", "input_per_mtok_usd", "output_per_mtok_usd"],
    "properties": {
      "threshold_tokens": { "type": "integer", "minimum": 1 },
      "input_per_mtok_usd": { "$ref": "#/$defs/decimal" },
      "output_per_mtok_usd": { "$ref": "#/$defs/decimal" }
    }
  }
}
```

New (add one property; required list unchanged so existing data still validates):

```json
"items": {
  "type": "object",
  "additionalProperties": false,
  "required": ["threshold_tokens", "input_per_mtok_usd", "output_per_mtok_usd"],
  "properties": {
    "threshold_tokens": { "type": "integer", "minimum": 1 },
    "input_per_mtok_usd": { "$ref": "#/$defs/decimal" },
    "output_per_mtok_usd": { "$ref": "#/$defs/decimal" },
    "cache_read_per_mtok_usd": { "$ref": "#/$defs/decimal" }
  }
}
```

**Semantics:** if a tier has `cache_read_per_mtok_usd`, the cache hit rate for prompts above that threshold uses this value (overrides the row-level `cache_read_per_mtok_usd`). Captures Gemini 2.5 Pro's `$0.25/MTok` cache hit rate above 200k.

### 2. Add row-level `cache_storage_per_mtok_per_hour_usd`

```json
"cache_storage_per_mtok_per_hour_usd": { "$ref": "#/$defs/decimal" }
```

**Semantics:** per-MTok-stored-per-hour rate for providers that bill explicit cache storage as a rental (Gemini, possibly others). Distinct from `cache_write_per_mtok_usd` (which is per-write). Both can coexist on a row (e.g. Anthropic uses per-write; Gemini uses per-storage-hour; some hypothetical provider could use both).

Naming preference: explicit `_per_hour` suffix to avoid confusion with `cache_write_per_mtok_usd`. The verbose name is OK because the field is optional and rarely set.

### 3. Add row-level `per_request_usd` and `per_search_usd`

```json
"per_request_usd": { "$ref": "#/$defs/decimal" },
"per_search_usd": { "$ref": "#/$defs/decimal" }
```

**Semantics:**

- `per_request_usd`: flat fee per API call, regardless of token volume. Currently Perplexity Sonar.
- `per_search_usd`: fee per search query the model issues (Perplexity Sonar Deep Research bills citation searches separately from generated tokens).

Both are additive to the per-token charges. Cost estimator should add them when present.

Why two fields instead of a generic `fees: {request, search, ...}` object: the two known fee types are sparse and concrete; an object adds nesting without clear benefit. If a third fee type lands (e.g. per-document, per-image-input fee), reconsider the structure.

### 4. Add `openrouter` to `deployment_options` enum

Current:

```json
"deployment_options": {
  "type": "array",
  "uniqueItems": true,
  "items": {
    "enum": [
      "native", "bedrock", "vertex", "azure", "together",
      "fireworks", "groq", "replicate", "dashscope"
    ]
  }
}
```

New:

```json
"items": {
  "enum": [
    "native", "bedrock", "vertex", "azure", "together",
    "fireworks", "groq", "replicate", "dashscope", "openrouter"
  ]
}
```

**Semantics:** `openrouter` is an aggregator that routes to multiple underlying hosts. Listing it in `deployment_options[]` means OpenRouter publishes the model with a stable canonical slug. The row's structured prices may match OpenRouter's aggregator-routed rate as long as `openrouter` is in the list and at least one direct host is also listed for transparency. Llama Maverick (PR4) can now claim `["together", "openrouter"]` with the OpenRouter rate.

`aliases[]` should include the OpenRouter model_id string when this option is set.

### Did not change

- `version: const 2` — stays. v2.1 is the spec version; the schema's `version` field is the data envelope version, not the schema version itself.
- `additionalProperties: false` — stays. New fields are explicitly declared.
- Decimal string pattern — stays.
- Any required field set — unchanged.
- All other fields — unchanged.

## Validation

- `pnpm costs:validate` continues to pass against all three current data files (existing rows already conform — no required-field changes).
- `pnpm site:build` continues to pass (TS additions are additive).
- jq referential checks continue to pass (no changes to alias / replaced_by semantics).

## Migration

Existing data is unchanged. No row is forced to populate the new fields. Existing consumers reading the canonical raw URLs see the same data.

For new rows or backfills:

- Future Gemini / Perplexity / Llama rows can use the new fields immediately.
- A separate backfill PR (or rolled into the next data PR per provider) can populate the new fields on existing rows where applicable.

## Risks

- **`cache_storage_per_mtok_per_hour_usd` is awkward to read at a glance.** Mitigation: rarely populated; renderer can format as "$X/MTok·hr" if surfaced in UI. If the verbosity bites, we can rename in a future minor.
- **`per_search_usd` may not capture every Perplexity fee dimension.** Sonar Deep Research has citation tokens billed at a separate rate. If that surfaces as a real consumer need, add `citation_tokens_per_mtok_usd` or similar.
- **`openrouter` in deployment_options blurs the "this is a real host" semantics.** Mitigation: when populated, require at least one direct host in the same list (cultural, not schema-enforced — document in `costs/README.md`).

## Out of scope (deferred)

- Per-modality input pricing (Gemini audio). Workaround: notes field. Promote when a second non-Gemini row needs it.
- Qwen-style percentage-of-tier cache caching. Workaround: notes field. Promote when a second case lands.
- Aggregator-as-meta semantics (OpenRouter is special-cased here; if a second aggregator like Replicate or LeptonAI emerges, we may want a separate `aggregators[]` field).
- Validator extensions beyond JSON Schema.
- Renderer / web UI surfacing the new fields.

## Compatibility

Strictly non-breaking. v2 consumers continue to validate. New optional fields are declared in the schema so producers can add them and validation will accept. Schema files are served at the canonical `$id` URLs and update in place.
