# Costs v0.2 — design

Status: approved 2026-05-17
Owner: @r13i
Supersedes: implicit v0.1 (initial ship 2026-05-05)

## Goal

Grow `costs/` from an early, narrow LLM/STT/TTS pricing dataset into the canonical, agent-first source teams reach for when comparing model costs and capabilities. Concretely: expand coverage to roughly 80 LLM / 25 STT / 20 TTS rows, evolve the schema to capture batch/cache/tier pricing and capability flags accurately, add two thin agent-facing Next.js routes (`/costs/index.json`, `/costs/per-model/{category}/{slug}.json`) so agents can resolve a model in one fetch, ship a cost-estimator endpoint, and add discoverability artifacts (`llms.txt`, `robots.txt`, `sitemap.xml`, JSON-LD) at the site root.

The dataset stays static, lives in JSON in the repo, and ships through the existing Next.js `web/` workspace and `raw.githubusercontent.com` URLs. No periodic scrapers, no MCP server, no vendor self-submission flow, no separate service, no new scripts under `scripts/costs/`, no committed generated artifacts, no changelog/RSS, no per-day diff files. Coverage and freshness rely on human PRs; tooling stays minimal.

## Non-goals

- Scrapers, scheduled refresh, auto-PR-on-diff bots.
- A separate `hail-costs-mcp` Go binary (or any new service).
- Vendor self-submission (`pricing.toml` ingestion).
- Live query API with rich filter semantics (`/costs/search?...` as a server endpoint).
- Per-row latency benchmarks as first-class columns (kept optional, under a `latency_benchmark` sub-object).
- Status page / per-vendor "last-successful-scrape" timestamps.
- Changelog endpoint, RSS feed, email alerts, per-day diff files. Git history is the changelog.
- New scripts under `scripts/costs/`, new GitHub Actions workflows, build-time artifact emission, committed generated JSON.
- Currency conversion. USD only; `currency: "USD"` documented but not stored per row.

## Architecture

```
costs/
  llm.json              ← source of truth (hand-edited, PR-reviewed)
  stt.json              ← source of truth
  tts.json              ← source of truth
  LICENSE               ← CC-BY-4.0 (unchanged)
  README.md             ← contribution + citation + canonical URLs
  schema/
    llm.schema.json     ← v2
    stt.schema.json     ← v2
    tts.schema.json     ← v2

scripts/costs/
  check-stale.mjs       ← existing, kept. No new scripts.

web/                                 ← Next.js zone, basePath: "/costs"
  app/
    (dispatch)/page.tsx              ← serves /costs (extended in Phase 3 with filters + calculator)
    (dispatch)/compare/page.tsx      ← existing, kept
    costs.md/route.ts                ← existing, kept
    schema/[name]/route.ts           ← existing, kept
    index.json/route.ts              ← NEW, serves /costs/index.json
    per-model/[category]/[slug]/route.ts   ← NEW, serves per-model JSON computed from source files
    estimate/route.ts                ← NEW (Phase 3), POST cost estimator
  lib/
    decimal.ts                       ← NEW, shared decimal-string arithmetic (route + UI)

# hail-website repo (not this monorepo): adds llms.txt, robots.txt, sitemap.xml at site root.
# Multi-zone rewrites stay unchanged; new routes are reachable under /costs/*.

.github/workflows/
  costs-validate.yml    ← existing, extend to validate against v2 schemas
  costs-stale.yml       ← existing, kept. No new workflows.
```

Two of the three new routes (`index.json`, `per-model/[category]/[slug]`) are `dynamic = 'force-static'` — Vercel renders them at build time and serves from the CDN with ETag/Last-Modified. `/costs/estimate` is the only POST route; it's a pure function over the source JSON.

## Schema v2

Bump `version: 1` → `version: 2` in all three schema files and data files. Migration runs in the same PR (Phase 0). No dual-version support.

`additionalProperties: false` stays in place to keep producer/consumer contracts tight.

### Shared changes (all three tables)

| Change                                                                             | Type                                                    | Required           | Notes                                                                                                                                             |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `last_verified` (existing)                                                         | `date`                                                  | yes                | "When we last checked."                                                                                                                           |
| **add** `last_changed_at`                                                          | `date`                                                  | yes                | "When the price last actually moved." Distinct from verification.                                                                                 |
| **add** `verification_method`                                                      | enum `manual-confirmed` \| `community-pr`               | yes                | `automated-scrape` and `vendor-submitted` deliberately excluded — phases dropped.                                                                 |
| **add** `confidence`                                                               | enum `high` \| `medium` \| `low`                        | no, default `high` | Applies to fields with measurement variance (latency, WER, TTFB).                                                                                 |
| **add** `deprecated_at`                                                            | `date`                                                  | no                 | EOL warning.                                                                                                                                      |
| **add** `replaced_by_model_id`                                                     | string                                                  | no                 | Points at successor row's `model_id`. Validator must check it resolves within the same file.                                                      |
| **add** `aliases[]`                                                                | array of strings                                        | no                 | E.g. `["anthropic.claude-opus-4-7-20250101-v1:0"]`.                                                                                               |
| **add** `deployment_options[]`                                                     | enum array                                              | no                 | One of `native`, `bedrock`, `vertex`, `azure`, `together`, `fireworks`, `groq`, `replicate`, `dashscope`. Single row covers all hosting variants. |
| **add** `free_tier`                                                                | object `{requests_per_day?: int, tokens_per_day?: int}` | no                 | First-class instead of buried in `notes`.                                                                                                         |
| **change** prices: `number` → `string` pattern `^(0\|[1-9][0-9]*)(\.[0-9]{1,8})?$` | string                                                  | —                  | Lossless decimals. Affects every `*_per_*_usd` field. Validator rejects float values.                                                             |

Acknowledged tradeoff: string-typed prices are slightly less readable than bare numbers. Correctness wins. Migration of the 19 existing rows is done by hand in the Phase 0 PR — no migration script. Reviewer eyeballs each row, which is appropriate at this scale.

### LLM-specific additions

- `cache_read_per_mtok_usd` (string, optional) — **rename of existing** `cached_input_per_mtok_usd`. Migration handles the rename.
- `cache_write_per_mtok_usd` (string, optional) — Anthropic-asymmetric write price.
- `batch_input_per_mtok_usd`, `batch_output_per_mtok_usd` (string, optional) — industry-standard 50% discount tier.
- `pricing_tiers[]` (optional) — array of `{threshold_tokens: int, input_per_mtok_usd: string, output_per_mtok_usd: string}`. Covers Gemini long-context (price changes above 200k tokens) and GPT-5 usage tiers uniformly. Replaces the originally suggested "second row" approach.
- `reasoning_tokens_billed` (boolean, optional) — important for o-series and Gemini thinking variants.
- `supports_tool_use`, `supports_vision`, `supports_audio_in`, `supports_audio_out`, `supports_pdf` (booleans, optional) — promote from the loose `modalities` array, which stays in place for backward read compatibility.
- `latency_benchmark` (object, optional) — `{source_url, ttft_ms?, output_tps?, measured_at, confidence}`. Top-level `output_tokens_per_sec` and `time_to_first_token_ms` are deliberately **not** promoted; benchmarks vary 5× by region/load.
- `knowledge_cutoff` — already exists, kept.

### STT-specific additions

- `diarization_per_minute_usd` (string, optional) — explicit price when `diarization: "extra-cost"`. Both fields may coexist.
- `realtime_latency_ms` (integer, optional, paired with `confidence`).
- `punctuation_included` (boolean, optional).
- `formatting_included` (boolean, optional).
- `pii_redaction_per_minute_usd` (string, optional).
- `min_billed_seconds` (integer, optional) — some providers round up to 15s.
- `max_audio_minutes_per_file` (integer, optional).
- `concurrent_streams_included` (integer, optional).
- `wer_benchmark` — already structured; keep, plus `confidence` next to it.

### TTS-specific additions

- `voices_count`, `voices_premium_count` (integers, optional).
- `cloning` — existing structured field; **extend** with optional `min_seconds: int`. Backward-compatible.
- `streaming_supported` (boolean, optional).
- `sample_rates_hz[]` (integer array, optional).
- **rename** `ssml_support` → `ssml_supported` for naming consistency with other booleans. Migration handles it.
- `emotion_control_supported` (boolean, optional).
- `min_billed_chars` (integer, optional).
- Backfill `time_to_first_byte_ms` for OpenAI and Groq rows during Phase 1.

## Data expansion (Phase 1)

Target counts: ~80 LLM, ~25 STT, ~20 TTS rows. All `verification_method: manual-confirmed`. Two-source rule applied per row (see Trust below). Specific coverage targets from the brief:

**LLM** — Anthropic (Haiku 4.5, Sonnet 4.5, Opus 4.5, Sonnet 3.7, Haiku 3.5), OpenAI (GPT-5 mini/nano, GPT-4.1, GPT-4o, GPT-4o mini, o3, o4-mini, o1), Google (Gemini 2.5 Flash, 2.5 Flash-Lite, 2.0 Flash), Meta (Llama 4 Maverick, Llama 4 Scout, Llama 3.3 70B on Together/Fireworks/Groq/Bedrock — single row with `deployment_options[]`), Mistral (Large 2, Medium 3, Small 3, Codestral, Pixtral), DeepSeek (V3, R1, V4 full), Cohere (Command R+, R, A), xAI (Grok 4, Grok 3, Grok Code), Alibaba (Qwen 3 family on DashScope, Together), Perplexity Sonar. Bedrock/Vertex/Azure-only variants are captured via `deployment_options[]` and `aliases[]`, not separate rows.

**STT** — Deepgram Nova-3 medical/finance variants, AssemblyAI Universal-1 + Slam-1, Azure Speech batch + real-time, Google Speech-to-Text (Chirp, Chirp 2, Latest_long, Latest_short), Speechmatics, Rev.ai, Gladia, Fal.ai Whisper variants, Replicate Whisper, Soniox, Picovoice Leopard / Cheetah.

**TTS** — ElevenLabs (Multilingual v2, Turbo v2.5, Eleven v3), Cartesia (Sonic 2, Sonic Turbo), OpenAI gpt-4o-mini-tts, Google Cloud TTS (Studio, Neural2, WaveNet, Chirp 3 HD), Azure TTS (Neural, HD), PlayHT 2.0 + PlayDialog, Hume Octave, Inworld TTS, Resemble AI, Smallest.ai Lightning, Unreal Speech, Rime, LMNT, Deepgram Aura 2.

Coverage gets ratcheted in batches of ~10 rows per PR to keep review manageable.

## Agent-facing routes (Phase 2)

Two new Next.js route handlers, both `dynamic = 'force-static'` so Vercel caches them at the edge (ETag and Last-Modified from the CDN). Pattern matches the existing `costs.md/route.ts`. No scripts, no committed generated files.

| Path                                      | Shape                                                    | Notes                                                                                                                                     |
| ----------------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `/costs/index.json`                       | `{models: [{id, category, provider, slug, source_url}]}` | Flat lookup. `id` = `{category}/{slug}`. One fetch resolves "is this model in the dataset, and where's the row?"                          |
| `/costs/per-model/{category}/{slug}.json` | Full single-row payload with envelope.                   | `slug` = lowercased `model_id` with `[^a-z0-9-]` → `-`. Saves agents from loading the full 80-row LLM file when they only want one model. |
| `/costs/estimate`                         | POST.                                                    | Phase 3. Documented separately below.                                                                                                     |

**Site-root artifacts (hail-website repo, not this monorepo):**

| File                          | Notes                                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `https://hail.so/llms.txt`    | Root-of-site convention. Points at `/costs.md`, `/costs/index.json`, `/costs/schema/{llm,stt,tts}.json`. Brief site-purpose paragraph at top. |
| `https://hail.so/robots.txt`  | Explicit allow for `GPTBot`, `ClaudeBot`, `Google-Extended`, `PerplexityBot`, `CCBot`.                                                        |
| `https://hail.so/sitemap.xml` | All per-model URLs (`/costs/per-model/{category}/{slug}`) plus the existing top-level pages.                                                  |

A separate PR in `hail-website` adds these three files in Phase 2; this monorepo cannot reach them due to basePath.

**JSON-LD** — `<script type="application/ld+json">` Product+Offer blocks rendered into the `/costs` page and per-model pages from the same source JSON at request time. No script, no separate dataset; same source as everywhere else.

**Changelog** — deliberately not provided as an endpoint. Consumers wanting price-change history read `git log -p costs/llm.json` (or the equivalent on GitHub). The `costs/README.md` "Agent usage" section shows the canonical command.

## Cost estimator (Phase 3)

**Server route** — `web/app/estimate/route.ts` (served at `/costs/estimate` via the workspace basePath). POST body:

```json
{
  "model_id": "claude-opus-4-7",
  "input_tokens": 12000,
  "output_tokens": 800,
  "cached_input_tokens": 4000,
  "batch": false
}
```

Response:

```json
{
  "model_id": "claude-opus-4-7",
  "usd": "0.0612",
  "breakdown": [
    {
      "component": "input",
      "tokens": 8000,
      "rate_per_mtok_usd": "...",
      "usd": "..."
    },
    {
      "component": "cached_input",
      "tokens": 4000,
      "rate_per_mtok_usd": "...",
      "usd": "..."
    },
    {
      "component": "output",
      "tokens": 800,
      "rate_per_mtok_usd": "...",
      "usd": "..."
    }
  ]
}
```

Pure function over `costs/llm.json` (and `costs/stt.json` / `costs/tts.json` for analogous unit shapes — STT takes `minutes`, TTS takes `chars`). All arithmetic in decimal-string space using a small helper at `web/lib/decimal.ts` to avoid float drift. Same helper is imported by the UI calculator. No separate Node script.

**UI on `/costs`**:

- Filter chips: provider multi-select, modality, price range, context size.
- Filter state in querystring for permalinks (`?provider=openai,anthropic&max_input=5`).
- Calculator panel: input monthly volume → table sorted by monthly cost.
- "Cheapest in class" badges — criteria documented in `/costs.md` (e.g. "lowest input price among LLMs with ≥128k context and `supports_tool_use: true`"). Computed at render time from the source JSON.

No new runtime dependencies. Use `URLSearchParams` directly; defer `nuqs` unless the page already pulls it in.

## Trust and provenance

**Per-row source link** — already required via `source_url`. Continues.

**Verification log** — surfaced inline on the rendered `/costs` page and per-model pages: "Last verified YYYY-MM-DD by @handle". PR linking is deliberately out of scope; readers wanting more can click through to the GitHub blame.

**Two-source rule** — documented in `costs/README.md`. For any price-affecting field change, the PR description must contain either two independent source links or an explicit acknowledgment that a second source is unavailable plus `confidence: medium`. Not enforced in CI — culture + review.

**Confidence column** — applies to `latency_benchmark`, `realtime_latency_ms`, `wer_benchmark`, `time_to_first_byte_ms`. Default `high`; downgrade when benchmark methodology is unknown or single-sourced.

## Data quality conventions

- **Currency**: USD only. `currency: "USD"` documented in `costs/README.md`; not stored per row.
- **Units**: fixed at ingest. Prices are per 1M tokens, per minute, per 1M characters respectively. Conversion math documented in the schema descriptions.
- **Decimal precision**: prices stored as strings matching `^(0|[1-9][0-9]*)(\.[0-9]{1,8})?$`. Validator rejects floats.
- **Free tier**: structured object `{requests_per_day?, tokens_per_day?}`. No free-text in `notes`.
- **Volume discount tiers**: array via `pricing_tiers[]`. Base price stays in the flat fields.

## Versioning and citation (Phase 4)

- GitHub release `costs-v0.2.0` cut when Phase 0 + Phase 1 ship. Subsequent releases follow semver:
  - **major** for schema-breaking changes
  - **minor** for new optional fields or new rows
  - **patch** for in-place corrections (price fixes, alias additions)
- Citation snippet in `costs/README.md`: `Hail Costs Dataset v0.X.Y, https://hail.so/costs, accessed YYYY-MM-DD`.
- LiteLLM upstream PR: one PR per category (LLM, STT, TTS), sourced from our `costs/*.json`, with a "Data sourced from hail.so/costs (CC-BY-4.0)" backlink in the PR description.

## Phasing

```
Phase 0  schema v2 + decimals-as-strings + last_changed_at + verification_method + hand-migration
Phase 1  data expansion to ~80/25/20 rows (manual-confirmed only)
Phase 2  /costs/index.json + /costs/per-model/* route handlers + JSON-LD + llms.txt/robots.txt/sitemap via hail-website PR
Phase 3  /costs/estimate route + calculator/filter UI on /costs
Phase 4  versioned releases + citation guide + LiteLLM upstream PR
```

Each phase is independently shippable. Phase 0 blocks Phase 1; otherwise no hard ordering across phases beyond developer attention.

## Risks and open questions

- **Price-as-string ergonomics**: `0.0008` vs `"0.0008"` is a real readability hit when scanning `llm.json` in a PR. Mitigation: the validator catches accidental float reintroductions; the rendered `/costs` table reads identically. If reviewers find it painful in practice, revisit after Phase 1.
- **`aliases[]` and `deployment_options[]` collisions across rows**: two rows might claim the same alias. Validator should reject duplicate aliases across the same file. Spec'd in Phase 0 work.
- **`replaced_by_model_id` referential integrity**: validator must resolve it within the same file. Spec'd in Phase 0 work.
- **Hand-migration risk**: 19 rows × ~3 price fields = ~57 string conversions plus two renames. Reviewer-friendly at this scale; would be untenable at 100+. The migration PR is one-shot, so the risk does not recur.
- **Out-of-scope items previously specced** (scrapers, MCP server, vendor self-submission, status page, changelog endpoint, RSS, per-day diffs, generation scripts, generated-artifact workflows) — kept in this document's non-goals to make the deletion explicit.

## Compatibility

`costs/llm.json`, `costs/stt.json`, `costs/tts.json` remain at the same canonical paths. Existing consumers fetching the raw GitHub URLs continue to work, but must handle:

- `version: 2` instead of `1`
- prices as strings
- `cached_input_per_mtok_usd` renamed to `cache_read_per_mtok_usd` (LLM)
- `tool_use` renamed to `supports_tool_use` (LLM) — for consistency with the new `supports_*` booleans
- `ssml_support` renamed to `ssml_supported` (TTS)

Release notes for `costs-v0.2.0` must call these out explicitly. No deprecation window — v0.x means consumers are forewarned.
