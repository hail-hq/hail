# Costs v0.2 — Phase 1 design (data expansion)

Status: drafted 2026-05-17
Owner: @r13i
Depends on: [Phase 0 design](./2026-05-17-costs-v0.2-design.md) (schema v2 already shipped)

## Goal

Expand `costs/{llm,stt,tts}.json` from the 19 rows that shipped at end of Phase 0 to roughly 80 LLM / 25 STT / 20 TTS rows. Each new row must be `verification_method: manual-confirmed` with the two-source rule applied. The shape and tooling are already in place from Phase 0 — Phase 1 is data work only.

`~80/25/20` is a target, not a contract. Realistic landing is 50-80 LLM, 25 STT, 20 TTS; ship what verifies cleanly.

## Non-goals

- Schema changes (Phase 0 closed v2; no v3 in Phase 1).
- New CI workflows or scripts.
- Latency benchmarks (`latency_benchmark` is optional and left empty for Phase 1; pulling from ArtificialAnalysis is a separate effort).
- Per-provider hosting deep-dives (Bedrock/Vertex/Azure go in `deployment_options[]` and `aliases[]`, single row per logical model).
- Hitting an exact row count.

## Architecture

Data-only. No new files, no new code paths. Each PR touches `costs/llm.json`, `costs/stt.json`, or `costs/tts.json` and optionally `costs/README.md` if conventions need clarification.

## Batching strategy

**Provider-family PRs.** One PR per provider (or tight provider cluster), adding that provider's new rows plus opportunistically backfilling existing rows for the same provider with newly-researchable v2 fields. Each PR review-sized: 5–15 rows. ~15 PRs total (see order below).

Rejected alternatives:

- Mega-PR per category (75+ rows): unreviewable; two-source discipline collapses.
- One PR per row (100+ PRs): merge thrash, review fatigue.

## Per-row conventions

Already enforced by the v2 schema and Phase 0's CI checks. Restating for Phase 1 clarity:

- `verification_method: manual-confirmed`
- `verified_by: r13i` (the dataset owner does a final eyeball before merge)
- `last_verified` and `last_changed_at` set to PR-merge date
- `source_url` points at the vendor's canonical pricing page
- **Two-source rule**: PR description includes the vendor pricing URL **and** a secondary source. Secondary can be OpenRouter, ArtificialAnalysis, a vendor announcement / changelog, vendor API docs, or a third-party aggregator. If a second source is genuinely unavailable, set `confidence: medium` on the affected row and call it out in the PR.
- `confidence: high` is the default; `medium` for fields where benchmark methodology is unclear or single-sourced; `low` is rarely used and should trigger PR-time discussion.
- `aliases[]`: populated with Bedrock / Vertex / Azure / OpenRouter model IDs where the model is hosted under different names.
- `deployment_options[]`: populated when the model is hosted on multiple platforms. A single row covers all hosting variants.
- `pricing_tiers[]`: populated for any model with documented tiered pricing (Gemini long-context, GPT-5 usage tiers).
- `supports_*` booleans: populated truthfully. `reasoning_tokens_billed: true` for o-series, Gemini thinking variants, Claude with extended thinking enabled.
- Field ordering inside each row follows the pattern established in the migrated Phase 0 rows (provider → identifiers → prices → modalities → capability booleans → verification metadata → notes).

## Per-PR checklist (subagent + reviewer)

1. **Draft.** Subagent fetches the vendor's pricing page, drafts the new rows + backfill, populates all known v2 fields, leaves unknowable fields unset.
2. **Sources.** PR description lists two independent links per price change (vendor pricing page + secondary). One link per row if multiple rows.
3. **Local validation.** `pnpm costs:validate` passes locally before push.
4. **Local web build.** `pnpm site:build` passes locally. (Added because of the Phase 0 / web break — data values flow into rendered prices, and any regression in price formatting catches here.)
5. **Open the PR.** Title: `feat(costs): add <provider> rows` (no `!` — additive, non-breaking).
6. **Eyeball.** Owner reviews the rendered diff, spot-checks 1-2 rows against the vendor page, merges or requests fixes.

## Execution model

Subagent-assisted research. For each PR:

- I dispatch a subagent with `WebFetch` access to draft the rows. Subagent reads the vendor pricing page, drafts JSON entries fitting the v2 schema, finds a secondary source, and prepares the PR description.
- The owner (you) reviews the draft + sources, edits anything wrong, validates locally, opens the PR.

You can switch to manual research per-PR (e.g., if a vendor's pricing page is unscrapable or you want to do a specific provider hands-on). The conventions and per-PR checklist apply either way.

## Risks and open questions

- **Two-source rule rigor.** Some providers (smaller TTS shops, fringe STT) genuinely lack a secondary source. Falling back to `confidence: medium` is fine, but the PR review needs to actually engage with that choice rather than rubber-stamp it.
- **Price drift during Phase 1.** A provider's pricing may change mid-PR (e.g. DeepSeek did 2026-04-26). The two-source check at draft time + the merge-date `last_verified` are the mitigation; drift after merge gets caught by the weekly stale check.
- **`aliases[]` and `deployment_options[]` coverage.** The first few PRs will set the convention for how thoroughly to populate these. Better to over-populate aliases for the first Anthropic + OpenAI rows so agents can resolve Bedrock / Azure model IDs from day 1.
- **`pricing_tiers[]` shape vs. reality.** Schema models a single threshold (`{threshold_tokens, input, output}`). Some providers (e.g. OpenAI's GPT-5 usage tiers) have multiple thresholds; the schema supports an array, so multiple entries land as multiple `pricing_tiers[]` items. Confirmed feasible; PR2 (OpenAI) is the first stress-test.
- **`free_tier` for STT/TTS.** The shape (`requests_per_day` / `tokens_per_day`) maps awkwardly onto audio-minute or character quotas. For Phase 1, leave `free_tier` empty on STT/TTS rows unless a provider clearly maps to one of the two keys. A schema follow-up can add `minutes_per_day` / `chars_per_day` later if needed.
- **Time budget.** 14 PRs × ~30 min each is 7 hours of focused work. Not a single sitting. Expected duration: several weeks of opportunistic batches. No deadline pressure — the dataset value compounds as it grows.

## Definition of done

Phase 1 is "done" when:

- All planned LLM provider families have at least one PR merged (PRs 1–9). LLM row count lands somewhere between 40 and 80.
- STT coverage at least 20 rows (target ~25).
- TTS coverage at least 16 rows (target ~20).
- `costs-v0.2.0` GitHub release is cut with notes pointing at the dataset and the citation snippet.
- README is updated to reflect the new row count if material (currently mentions no count).

Stretch goals (out of scope for "done" but allowed within Phase 1):

- LiteLLM upstream PR with the LLM dataset.
- Backfilling `latency_benchmark` from ArtificialAnalysis on the top 10 most-fetched models.

## Compatibility

No schema changes. v2 consumers stay green. Each PR is purely additive (or backfills optional fields). Any change to a required field (renames, removals) is out of scope for Phase 1 and would warrant its own breaking-change spec.
