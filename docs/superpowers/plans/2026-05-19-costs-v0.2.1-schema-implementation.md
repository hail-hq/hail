# Costs v0.2.1 Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply five non-breaking, additive extensions to the v2 LLM schema and update the TypeScript types to match. No data changes; no version bump (data envelope `version` stays at `2`).

**Architecture:** Two files modified — `costs/schema/llm.schema.json` (4 new optional fields + 1 enum value) and `web/lib/types.ts` (TS type additions to match). Existing data validates unchanged. The Next.js build verifies the TS additions don't break the renderer.

**Tech Stack:** JSON Schema 2020-12, TypeScript, Next.js 16. Validation via `pnpm costs:validate` (Python `check-jsonschema` 0.29.4 via pipx); web build via `pnpm site:build`.

**Source spec:** [`docs/superpowers/specs/2026-05-19-costs-v0.2.1-schema-design.md`](../specs/2026-05-19-costs-v0.2.1-schema-design.md)

```
feat(costs)!: extend v2 schema with cache tiers, per-request fees, openrouter

Non-breaking additive extensions to the LLM schema (no data envelope
version bump; existing rows validate unchanged):

- pricing_tiers[] items gain optional cache_read_per_mtok_usd to
  capture Gemini 2.5 Pro's per-tier cache hit rate (and similar
  per-tier cache pricing on other providers).
- Add row-level cache_storage_per_mtok_per_hour_usd for providers
  that bill explicit context caching as per-MTok-stored-per-hour
  storage (Gemini, Alibaba DashScope) — distinct from cache_write
  which is per-write.
- Add row-level per_request_usd and per_search_usd for providers
  with flat per-call or per-search fees (Perplexity Sonar family).
- Add openrouter to the deployment_options enum so aggregator-routed
  pricing can be claimed without forcing a direct-host-only listing.

Updates web/lib/types.ts with the matching optional fields. No data
backfill in this PR — existing rows are unchanged; future Gemini /
Perplexity / Llama rows (or targeted backfills) can populate the new
fields.

The `!` in the commit type reflects that consumers strictly checking
deployment_options enums or pricing_tiers item shapes against
hand-written types may need to extend their schemas; existing v2
producers and validators are unaffected.
```
