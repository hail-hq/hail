# Costs v2.2 Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply four additive schema extensions across all three category schemas, plus matching TypeScript types. Non-breaking, no `version` bump, no data migration.

**Architecture:** Edit three JSON Schema files (LLM, STT, TTS) and `web/lib/types.ts`. LLM gets `audio_input_per_mtok_usd` + `aggregators[]`. STT and TTS get `price_per_second_usd` + `aggregators[]`, with their primary price fields relaxed from "required" to "one-of" via `anyOf`. Probe accept/reject cases verify the constraints actually enforce.

**Tech Stack:** JSON Schema 2020-12, TypeScript, Next.js 16. Validation via `pnpm costs:validate` (Python `check-jsonschema` 0.29.4 via pipx); web build via `pnpm site:build`.

**Source spec:** [`docs/superpowers/specs/2026-05-26-costs-v2.2-design.md`](../specs/2026-05-26-costs-v2.2-design.md)

- The `openrouter` enum value stays in `deployment_options[]` per the spec's back-compat note. The spec mentioned a `deprecated: true` annotation as informational only — JSON Schema doesn't have a clean way to mark an enum value as deprecated, and the schema reader would have to follow the convention themselves. Skipped in this PR to avoid bloating the schema description; documented in `costs/README.md` would be the right place to land this guidance in a later docs pass.
- Probe files (Task 1 Steps 7-9) live in `/tmp/`, not in the repo; deleted after use.
- The `anyOf` constraint placement: in JSON Schema 2020-12, `anyOf` is a sibling to `properties` / `required` at the same object level. Placed it directly after `required` on the model `$defs` block (Task 1 Step 4a / 5a).
- No data backfill of existing rows. The spec deliberately defers that to a follow-up data PR so subagents can verify each promotion against vendor sources.
