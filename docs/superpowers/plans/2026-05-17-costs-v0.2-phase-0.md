# Costs v0.2 — Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate `costs/{llm,stt,tts}.json` and their JSON Schemas from v1 to v2 — adding shared fields (`last_changed_at`, `verification_method`, `aliases`, `deployment_options`, `free_tier`, `confidence`, `deprecated_at`, `replaced_by_model_id`), category-specific fields, decimal-string prices, and a few renames — and hand-migrate the existing 19 rows. Phase 0 only — Phases 1–4 get their own plans.

**Architecture:** Six tasks. Tasks 1–3 each migrate one category's schema + data atomically (single commit, repo stays green). Task 4 extends `costs-validate.yml` with `jq`-based referential checks (no new script files). Task 5 documents v2 in `costs/README.md`. Task 6 is a final cross-cutting verification.

**Tech Stack:** JSON Schema (draft 2020-12), `check-jsonschema` 0.29.4 (Python via pipx), `jq` (in CI workflow), pnpm scripts. No new Node scripts.

**Source spec:** [`docs/superpowers/specs/2026-05-17-costs-v0.2-design.md`](../specs/2026-05-17-costs-v0.2-design.md)

### Task 4: Add referential checks to costs-validate workflow

**Files:**

- Modify: `.github/workflows/costs-validate.yml`

JSON Schema alone cannot enforce cross-row uniqueness (`aliases[]` should not duplicate across rows in the same file) or referential integrity (`replaced_by_model_id` must resolve to another `model_id` in the same file). We add two `jq` steps to the existing workflow — no new script file.

- [ ] **Step 1: Replace `.github/workflows/costs-validate.yml`**

```yaml
name: costs-validate

on:
  pull_request:
    paths:
      - "costs/**"
      - ".github/workflows/costs-validate.yml"

concurrency:
  group: costs-validate-${{ github.ref }}
  cancel-in-progress: true

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - name: Install check-jsonschema
        run: pip install check-jsonschema==0.29.4
      - name: Validate LLM data
        run: check-jsonschema --schemafile costs/schema/llm.schema.json costs/llm.json
      - name: Validate STT data
        run: check-jsonschema --schemafile costs/schema/stt.schema.json costs/stt.json
      - name: Validate TTS data
        run: check-jsonschema --schemafile costs/schema/tts.schema.json costs/tts.json
      - name: Check alias uniqueness within each file
        run: |
          for f in costs/llm.json costs/stt.json costs/tts.json; do
            dupes=$(jq -r '[.models[] | .aliases // [] | .[]] | group_by(.) | map(select(length > 1) | .[0])' "$f")
            if [ "$dupes" != "[]" ]; then
              echo "::error file=$f::duplicate aliases: $dupes"
              exit 1
            fi
          done
      - name: Check replaced_by_model_id resolves within each file
        run: |
          for f in costs/llm.json costs/stt.json costs/tts.json; do
            unresolved=$(jq -r '
              (.models | map(.model_id)) as $ids
              | [.models[] | select(.replaced_by_model_id != null) | select((.replaced_by_model_id as $r | $ids | index($r)) == null) | .model_id]
            ' "$f")
            if [ "$unresolved" != "[]" ]; then
              echo "::error file=$f::replaced_by_model_id does not resolve: $unresolved"
              exit 1
            fi
          done
```

````markdown
# Model Costs

Public, validated cost and capability data for AI model providers — LLMs, speech-to-text, and text-to-speech.

- LLMs: <https://raw.githubusercontent.com/hail-hq/hail/main/costs/llm.json>
- STT: <https://raw.githubusercontent.com/hail-hq/hail/main/costs/stt.json>

- <https://hail.so/costs/schema/stt.json>
- <https://hail.so/costs/schema/tts.json>

## How AI agents should use this

The data files share a common envelope: `{ version, license, models[] }`. Every model row has `provider`, `model_id`, `display_name`, primary price fields (as decimal strings, e.g. `"5.0"`), `last_verified`, `last_changed_at`, `verification_method`, `verified_by`, and `source_url`. See the JSON Schemas above for the exact shape per category.

Canonical fetch pattern:

```bash
curl -s https://raw.githubusercontent.com/hail-hq/hail/main/costs/llm.json | jq '.models[] | select(.model_id == "claude-opus-4-7")'
```
````

```bash
curl -s https://raw.githubusercontent.com/hail-hq/hail/main/costs/llm.json | jq '.models[] | select(.aliases // [] | index("anthropic.claude-opus-4-7-20250101-v1:0"))'
```

Price history for a row (changelog):

```bash
git log -p costs/llm.json | grep -A 5 '"model_id": "claude-opus-4-7"'
```

## Currency and units

- All prices are in USD (`currency: "USD"` implicit).
- LLM prices are per 1M tokens (`*_per_mtok_usd`).
- STT prices are per minute of audio (`price_per_minute_usd`).
- TTS prices are per 1M characters of input (`price_per_1m_chars_usd`).
- Prices are stored as decimal strings — `"0.0048"`, not `0.0048` — to avoid float roundtrip errors. Parse with `Decimal` (Python), `BigInt`-aware libraries (JS), or `decimal.Decimal` equivalents.

## How to contribute a cost update

1. Fork the repo or use GitHub's web editor.
