### Task 2: Validate and build

**Files:** none modified.

Confirm the drafted JSON validates against the v2 schema and the Next.js renderer still builds cleanly.

- [ ] **Step 1: Run the validator**

Run: `pnpm costs:validate`

Expected: ALL THREE sections (LLM, STT, TTS) PASS with `ok -- validation done` for each. The LLM section is the one your changes touched; STT and TTS should remain unchanged.

If FAIL on LLM: the validator output identifies the offending row(s) and field(s). Fix the JSON (typos, wrong types, missing required field, extra unknown field, malformed decimal string, unknown enum value) and re-run. Common failures:

- Price as JSON number (`5.0`) instead of string (`"5.0"`) — schema enforces `$defs/decimal` pattern
- Missing `last_changed_at` or `verification_method` — required in v2
- `replaced_by_model_id` pointing at a model not present in the file — but this only fires in CI's jq step, not local check-jsonschema
- Unknown field — `additionalProperties: false`
- Duplicate `aliases` value across rows — fires in CI jq step, not locally

- [ ] **Step 2: Run the jq referential checks locally**

CI runs these on the workflow, but it's cheaper to catch them now.

```bash
cd /Users/r/playground/hail
for f in costs/llm.json costs/stt.json costs/tts.json; do
  dupes=$(jq -r '[.models[] | .aliases // [] | .[]] | group_by(.) | map(select(length > 1) | .[0])' "$f")
  echo "$f aliases: $dupes"
  unresolved=$(jq -r '(.models | map(.model_id)) as $ids | [.models[] | select(.replaced_by_model_id != null) | select((.replaced_by_model_id as $r | $ids | index($r)) == null) | .model_id]' "$f")
  echo "$f replaced_by: $unresolved"
done
```

Expected: every line ends with `[]`. If `aliases` lists a non-empty array, you have a duplicate Bedrock/Vertex ID across rows — fix. If `replaced_by` lists a non-empty array, a deprecated row points at a `model_id` that does not exist — either add the target model in this PR or drop the `replaced_by_model_id` field.

- [ ] **Step 3: Run the Next.js build**

If FAIL: read the TypeScript error. The most likely cause is a missing required field that the TS types declare as required (`last_changed_at`, `verification_method`). Add the field to the offending row and re-run.
