## Scope (~6 rows)

### Azure Speech (2 rows)

Azure Speech is one service with two modes (real-time and batch) at different per-hour rates. Two row strategies:

- **Two rows**, one per mode: `azure-speech-realtime` + `azure-speech-batch`
- Use canonical model_id strings; if Azure publishes specific deployment names (`Standard`, `Custom Speech`, etc.), prefer those

### Google STT (4 rows)

Verify against Google's published model overview:

1. `chirp` — first-generation Universal Speech Model
2. `chirp-2` — second-gen multilingual; pricing typically per-second
3. `latest_long` — long-form transcription
4. `latest_short` — short-form (≤60s) transcription

If `latest_long` / `latest_short` are deprecated in favor of Chirp, mark them so.

## Per-row data (STT schema)

Same fields/conventions as PR10. Key reminders:

- `provider`: `"Microsoft Azure"` for Azure, `"Google"` for Google
- `provider_url`: `"https://azure.microsoft.com"` or `"https://cloud.google.com"`
- `price_per_minute_usd`: required decimal string. If vendor publishes $/hour, convert to per-minute (e.g. $0.36/hr → "0.006")
- `price_per_minute_batch_usd`: optional (Azure has batch mode; Google may not advertise as distinct rate)
- `languages`: array or `"N+"` form
- `streaming`: bool — Azure real-time = true; Azure batch = false; Google Latest_long = file-based (false); Google Chirp = supports streaming (true); etc.
- `realtime`: bool
- `diarization`, `diarization_per_minute_usd`: per docs
- `deployment_options`: at minimum `["native"]`. For Azure, that may be `["azure"]` (native to Azure); for Google, `["native"]` typically means Google Cloud directly; `["vertex"]` only if Speech-to-Text is also published on Vertex AI.
- `last_verified: "2026-05-19"`
- `verification_method: "manual-confirmed"`, `verified_by: "r13i"`
- `source_url`: vendor pricing page
- `notes`: 1-3 sentences (Azure modes, Google tier discounts, etc.)
